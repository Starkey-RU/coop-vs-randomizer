# Вопросы для Архитектора (HD2 Attrition Randomizer)

## Контекст
У нас есть рабочий фундамент на React + Vite + Tailwind v4 + Zustand + Firebase Realtime Database. 
База данных (`database.json`) готова и содержит: Primary, Secondary, Grenades, Armor (light/med/heavy), Boosters (с логикой Must-Have/LIFO+FIFO), и Stratagems (классифицированные по слотам: Weapon, Backpack, Weapon+Backpack, Vehicle, Offensive/Defensive).

Текущий рабочий режим: **Chaos Random Attrition** (хост жмёт кнопку, распределяется случайный лут на всех, пулы истощаются).

Нам нужно спроектировать 3 новых режима:
1. **Co-op Attrition**
2. **Random Pool Attrition (Операции на 3 миссии)**
3. **Versus Mode**

## Вопросы для продумывания архитектуры:

### 1. Co-op Attrition (Ручной Драфт)
В этом режиме игроки *сами* выбирают себе снаряжение из общего, единого пула базы, и после нажатия Deploy выбранное сгорает.
* **Q1.1:** Как технически реализовать интерфейс и синхронизацию Firebase, чтобы избежать race conditions? Если два игрока одновременно кликают на один и тот же "Autocannon", кому он достанется? Стоит ли делать пошаговый драфт (Turn-based) или хватать на лету (Real-time First-Come-First-Serve)?
* **Q1.2:** Как хранить стейт "драфта" в Firebase до нажатия Deploy?

### 2. Random Pool Attrition
В этом режиме перед началом Операции (которая состоит из 3 миссий) генерируется ограниченный пул ровно на 12 лодаутов (по 3 лодаута на 4 игроков).
* **Q2.1:** Как мы генерируем этот пул? Аналогично 12-кратному вызову генератора Chaos Mode, чтобы учесть баланс рюкзаков и мехов?
* **Q2.2:** Игроки делят этот пул сразу на все 3 миссии вперёд, или перед каждой из трёх миссий они выбирают из остатков этого "мини-пула"? Как это лучше отобразить в UI?

### 3. Versus Mode & Score Tracking
Пользователь упоминал Randomizer COOP/Versus. 
* **Q3.1:** Как организовать лобби? 2v2 или 1v1? 
* **Q3.2:** Выдаём ли мы обеим командам *одинаковые* лут-пулы (seed-based) для честности, или они истощают один общий пул на 8 человек? 
* **Q3.3:** Как реализовать интерфейс подсчёта очков (Objectives completed / Deaths / Kills)? Нужна ли для этого отдельная сущность State machine в Firebase?

### 4. Firebase Data Structure
* **Q4.1:** Сейчас структура лобби имеет вид `rooms/CODE/`. Как её лучше масштабировать, чтобы вместить статусы `lobby -> drafting -> round_1 -> round_2 -> round_3 -> finished`?
